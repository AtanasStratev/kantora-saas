# ADR-0008: Одитен журнал само за добавяне

Статус: прието (Фаза 0), 2026-11-14

## Решение
- Таблица `audit_log` (партиционирана по месец). Общ тригер `AFTER INSERT/UPDATE/DELETE`
  върху всички бизнес таблици записва: `office_id`, `company_id`, `user_id`, IP,
  user agent, време, таблица, ключ, действие, `old`/`new` (jsonb, само променените полета).
- Потребителят и IP-то идват от `SET LOCAL app.user_id/app.ip` в `withTenant`. Ако липсват
  при промяна на данни, тригерът отказва промяната.
- Append-only: `app_user` има само INSERT и SELECT (през RLS); тригер забранява UPDATE и
  DELETE за всички роли, включително собственика на таблицата.
- Хеш-верига: всеки ред съдържа `hash = sha256(prev_hash || row)` по кантора. Нощна задача
  проверява веригата.
- Изглед в UI: история на всеки документ/статия („кой какво промени“) и общ журнал за
  собственика.

## Последици
Журналът расте бързо. Партициите по месец позволяват архив в обектното хранилище след
срока на съхранение (срокът се проверява по закона).
