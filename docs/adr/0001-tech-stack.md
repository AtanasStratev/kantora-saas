# ADR-0001: Технологичен стек

Статус: прието (Фаза 0), 2026-11-14

## Контекст
PROMPT.md, т. 4 предлага стек по подразбиране. Собственикът работи сам и не е програмист,
затова поддръжката трябва да е проста: един език и малко движещи се части.

## Решение
Потвърждаваме стека от т. 4 със следните уточнения:

| Област | Избор | Защо |
|--------|-------|------|
| Език | TypeScript strict | Един език за клиент, сървър и задачи |
| Рамка | Next.js (App Router) + React | Сървърни компоненти и Server Actions намаляват API кода |
| Пакети | pnpm workspaces (монорепо) | Чистата логика (`packages/domain`) се отделя от UI и база |
| База | PostgreSQL 17 | RLS, numeric, constraint triggers, PITR |
| ORM | Drizzle ORM (само за типизирани заявки) | Близо до SQL, без „магия“; RLS и тригерите така или иначе са SQL |
| Миграции | SQL файлове с up/down, изпълнявани от **dbmate** | Виж ADR-0003 |
| Пари | `decimal.js` + `numeric` | Виж ADR-0004 |
| Валидация | Zod на всяка граница | |
| UI | Tailwind CSS + CSS променливи; Radix Primitives; TanStack Table/Virtual; cmdk | |
| Задачи | pg-boss | Виж ADR-0006 |
| Вход | Better Auth (с плъгина за TOTP) | Виж ADR-0005 |
| XML/XSD | `xmllint-wasm` | Без native компилация в Windows и CI |
| PDF | Playwright/Chromium (HTML → PDF) | Един шаблон за екран и печат |
| Excel | `exceljs` | |
| Тестове | Vitest (unit + integration с истински PostgreSQL), Playwright (e2e + снимки), axe-core | |
| Логове | pino с филтър за лични данни | |

## Отхвърлени алтернативи
- **Prisma:** по-тежка; RLS с `SET LOCAL` в транзакция и SQL тригерите се поддържат
  по-неудобно.
- **Отделен backend (NestJS) + SPA:** два проекта за поддръжка без реална полза на този етап.
- **Drizzle-kit за миграции:** не генерира down миграции (изискване 3.5).

## Уточнение 2026-11-14 (начало на Фаза 1)
- TypeScript е фиксиран на **6.0.x**: версия 7 (компилаторът на Go) още не се поддържа от
  typescript-eslint (peer `<6.1.0`). Преминаваме на 7, когато линтерът я поддържа.
- Node.js 26, pnpm 10 (инсталиран глобално през npm, защото Node 25+ не включва corepack).

## Последици
- Next.js се обновява често; фиксираме версиите и обновяваме съзнателно.
- Better Auth е по-млада библиотека: рискът е описан в `docs/risks.md`. Ако не издържи
  прегледа във Фаза 1, заменяме я със собствена реализация върху `@oslojs/otp` и
  `@node-rs/argon2`.
